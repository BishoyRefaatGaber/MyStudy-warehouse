## Configure Identity Providers

##### primary resource types
1. User 
	-  Users are entities that interact with the API server. 
	- The user resource represents an actor within the system.
2. Identity
	- The identity resource keeps a record of successful authentication attempts from a specific user and identity provider
3. Service Account
4. Group
5. Role
	- A role defines the API operations that a user has permissions to perform on specified resource types. 
	- You grant permissions to users, groups, and service accounts by assigning roles to them.
##### Common Identity Providers
1. HTPasswd
2. Keystone
3. LDAP
4. GitHub or GitHub Enterprise
5. OpenID Connect
##### Methods for authentication
1. OAuth access tokens
2. X.509 client certificates
> A newly installed OpenShift cluster provides two ways for authentication:
- kubeconfig file -> embeds an X.509 client certificate that never expires.
- kubeadmin virtual user

##### Managing Users with the HTPasswd Identity Provider
- The httpd-tools package provides the htpasswd utility.
``` bash
# Create the htpasswd
htpasswd -c -B -b /tmp/htpasswd student redhat123 
# Add or update credentials
htpasswd -b /tmp/htpasswd student redhat1234
# Delete credentials
htpasswd -D /tmp/htpasswd student
# Create an HTPasswd Secret
# Must be created to let openshift use it
oc create secret generic htpasswd-secret --from-file htpasswd=/root/htpasswd -n openshift-config
# When ever you update the date of the htpasswd (create, delete, edit a user) you need to update the secret on openshift
oc set data secret/htpasswd-secret --from-file htpasswd=/root/htpasswd -n openshift-config
# Configuring the OAuth Custom Resource
apiVersion: config.openshift.io/v1
kind: OAuth
metadata:
  name: cluster
spec:
  identityProviders:
  - name: my_htpasswd_provider
    mappingMethod: claim
    type: HTPasswd  
    htpasswd:
      fileData:
      name: htpasswd-secret
# Get the identities 
oc get identities
# Delete the identity
oc delete identity my_htpasswd_provider:manager
# Assigning Administrative Privileges
oc adm policy add-cluster-role-to-user cluster-admin administrator
# Delete the kubeadmin
oc delete secret kubeadmin -n kube-system
```
> The authentication operator handles the authentication cycle in openshift

## Role-based Access Control (RBAC)

##### RBAC Scope
1. Cluster RBAC
2. Local RBAC
##### Authorization Process 
1. Rule
	-  Allowed actions for objects or groups of objects.
2. Role
	- Sets of rules. Users and groups can be associated with multiple roles.
3. Binding
	- Assignment of users or groups to a role.
##### Managing RBAC with the CLI
``` bash
oc adm policy add-cluster-role-to-user cluster-role username
oc adm policy remove-cluster-role-from-user cluster-role username
oc adm policy who-can delete user
oc policy add-role-to-user role-name username -n project
```
##### Default Roles
1. admin -> can manage all project resources
2. basic-user
3. cluster-admin -> superuser access
4. cluster-status
5. cluster-reader -> access or view most of the objects
6. edit
7. self-provisioner -> can create their own projects.
8. view -> view project resources
##### User Types
1. Regular users
2. System users
3. Service accounts
##### Group Management
```bash
oc adm groups new lead-developers
oc adm groups add-users lead-developers user1
```
