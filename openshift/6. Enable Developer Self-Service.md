
## Project and Cluster Quotas

##### Resource Quotas
> When a resource quota exists in a namespace, Kubernetes prevents the creation of workloads that exceed the quota.

```yaml
apiVersion: v1
kind: ResourceQuota
metadata:
	name: memory
	namespace: example
spec:
	hard:
		limits.memory: 4Gi
		requests.memory: 2Gi
	scopes: {}
	scopeSelector: {}
```

> compute and object count quotas that you can include in the hard key.
1. limits.cpu
2. limits.memory
3. requests.cpu
4. requests.memory

## Applying Project Quotas
```bash 
oc create resourcequota example --hard=count/pods=1
```

```yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: example
  namespace: default
spec:
  hard:
    pods: '4'
    requests.cpu: '1'
    requests.memory: 1Gi
    limits.cpu: '2'
    limits.memory: 2Gi
```

> Problem with resource quotas
- Resource quotas are extensible, Kubernetes cannot verify that a resource quota is correct.
- ❌ oc create resourcequota example --hard=count/deployment=1
* ✅oc create resourcequota example --hard=count/deployments.apps=1
## Creating Quotas Across Multiple Projects
- Use cluster resource quotas
- Cluster resource quotas use selectors to choose which namespaces the quota applies to.
```yaml
apiVersion: quota.openshift.io/v1
kind: ClusterResourceQuota
metadata:
	name: example
spec:
	quota:
		hard:
			limits.cpu: 4
	selector:
		annotations: {}
		labels:
			matchLabels:
				kubernetes.io/metadata.name: example				
```
```bash
oc create clusterresourcequota example
--project-label-selector=group=dev --hard=requests.cpu=10
```

## Limit Ranges
- When a namespace has a quota, creating workloads fails if the workload does not define values for the limits or requests in the quota.
- Limit ranges do not affect existing pods.
- If you delete the deployment and run the oc create command again, then the deployment creates a pod with the applied limit range.
